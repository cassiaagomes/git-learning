# Modelo de Pull Request

As alterações feitas em um repositório precisam seguir boas práticas descritivas, para contextualizar o que foi feito, por que foi feito e como revisar. Abaixo segue um guia para que o PR seja bem sucedido. 

```md
## O que foi feito

- 

## Por que foi feito

- 

## Como revisar

- 

## Checklist

- [ ] Li os arquivos alterados.
- [ ] Conferi se a documentação está clara.
- [ ] Usei mensagens de commit objetivas.
- [ ] O PR está pequeno o suficiente para revisar.
```

## Exemplo preenchido

```md
## O que foi feito

- Adiciona documentação sobre conflitos de merge.
- Inclui uma prática guiada para simular conflito.

## Por que foi feito

- Para completar a trilha de estudos sobre Git.

## Como revisar

- Ler docs/09-conflitos-de-merge.md.
- Executar a prática em praticas/02-simulando-resolvendo-conflito.md.

## Checklist

- [x] Li os arquivos alterados.
- [x] Conferi se a documentação está clara.
- [x] Usei mensagens de commit objetivas.
- [x] O PR está pequeno o suficiente para revisar.
```
